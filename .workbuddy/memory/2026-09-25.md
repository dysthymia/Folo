# 2026-09-25 · Folo 信息处理 v3.2

## 已读条目退出处理队列（本轮新需求）

dysthymia 指出「已读的条目不用再处理，无论是否在队列里」。查实数据后实现：

**事实（一致副本 `VACUUM INTO` 核对，非只读连接）**

- `processing_inputs` 里 `pending` + `current` 共 3699 条，**全部 `read=1`**；存储 read 与实时 `entries.read` 零不一致（3699/3699）。
- 全部 8802 条 current input 已读 6508（74%）；`entries` 表 8802 条中已读 8363。
- 已出决策的 5103 条里 2809 条是已读 —— 历史上已经为已读内容付过模型费用。
- 未读且待处理 = **0**。所以「积压队列」100% 是已读堆积。

**实现**

- `processing-state.ts` 新增 `settleRead(skip, revive)`：已读 pending → `skipped` 终态；来源侧变回未读 → `pending`（避免「跳过」成为不可逆黑洞）。只动 `current=1`。
- `processing-engine.ts` 新增导出 `settleReadStates(store)` + 私有 `entryReadState()`（读态判定单一来源，`null` 不当作已读）。
- `processing-worker.ts` 在 `hydrateMaterials`（抓详情 + 可读性）**之前**调用 `settleReadStates`，否则已读条目仍会白跑正文抓取。
- 引擎在批层（`prepareNormalEntryBatches`）与原单篇路径各加一道读态闸门（双保险，直接调引擎也守口径）。
- `processing-reading-store.ts`：`pending` 口径排除 `skipped`，新增 `skipped` 计数与视图；`ReadingView` 与 API enum 同步加 `skipped`。
- 渲染层 `ProcessingReader.tsx` 计数条与视图列表加「已读跳过」；三语各 +2 键（`processing.reader.status.count.skipped`、`processing.reader.view.skipped`）。
- `processing-reader-client.ts` 的 `counts.skipped` 设为 **optional**（`.strict()` 会拒未知键，旧服务不返回它）。

**测试**：`processing-engine.test.ts` 新增 2 项（已读不调用模型 + 收敛映射；未读回到队列）；`processing-worker.test.ts` 新增 1 项（已读在抓详情前退出，`detail` 未被调用）；`processing-reading-store.test.ts` 新增 1 项（跳过与待处理分桶 + 独立视图）。原 `processing-worker.test.ts` 一处夹具 `read: true` 改为 `false`（该用例本意是验证正文水合，读态是无关噪声）。

**未做（留给决策）**：`capture` 仍会记录已读条目（只在处理阶段跳过）。若要让队列本身不再增长、DB 不再变大，需要改采集侧过滤；但采集时读态可能过期，且会让已读条目彻底不出现在工作台。

## 方法学纠错（读库必看）

- **`entry_decisions` 有 `release_version` 列**（`id/input_seq/generation/release_version/body/created_at`）；但 `processing_inputs.release_version` 会被 publish **重新盖章**，`JOIN processing_inputs GROUP BY i.release_version` 会把旧决策算到新版本头上 —— 必须用 `d.release_version`。
- `processing_inputs` 无 `published_at` 列；发布时间在 `json_extract(body,'$.publishedAt')`，`received_at` 是采集入库时间。
- `recent` 发布范围用 `receivedAt`（`automation-store.ts:365`），处理窗口用 `publishedAt`（`processing-engine.ts` 的 `withinWindow`）。
- `automation_draft` 无 `updated_at`；`jobs` 只有 `id/body/status`；`processing_material_state` 主键 `(source_key,item_id)`。
- 一致副本只能 `VACUUM INTO 'path'`（单引号）；只读连接漏 WAL。

## 方法学纠错第 7 条 + 新陷阱

- **第 7 条：隐藏不是 `policy` 上的字段，而是 `body.status === "hide"`。** `policy` 真实形状 = `{standalone:"auto"|"always"|"never", aggregation:"allow"|"deny", rewrite:"allow"|"deny"}`，**没有 `hidden`/`presentation`**。判定在 `processing-reading-store.ts:855` `entryHidden()`：`override.mode==='hide' || (override.mode!=='restore' && standalone!=='always' && (standalone==='never' || status==='hide'))`。
- `rule_set_releases` 主键是 **`version`**（不是 `id`）；`sources` 只有 `key/body/active`，标题在 `json_extract(body,'$.title')`。
- i18n 两种形状：仓库 `locales/<ns>/<lang>.json` 是**扁平点号键**，产物 `/locales/<lang>.js` 是**嵌套对象**；权威来源是 `LocaleCache.shared.set(lang)` 写回 `localStorage["follow:locale-zh-CN"]` 的那份（82810B）。
- 条目列虚拟滚动：滚动容器必须**从 `[data-entry-id]` 向上找**；`page.evaluate` 只序列化函数体，滚动逻辑必须自包含。
