## 二、真机数据核对抓到一个真 bug（提交 0ade0da6c）

用业务库 `VACUUM INTO` 副本 + 源码 harness（沿用 9-21 的 `/tmp/folo-dedupe-offline/roles.mts` 套路）
核对，发现 **`restored` 角标永远不会出现**：

`roles()` 里恢复分支写成「当前角色是 hidden 或 merged 才覆盖成 restored」，但恢复覆盖本身已经让
`entryHidden()` 返回 false —— **同一次投影里根本不会为它产生 hidden 角色**，那条判断对 hidden
永不成立。结果：点「恢复」条目确实回到列表了，但「已手动恢复」角标看不到（`merged` 那条路正常）。

修法：改判「若没有这次恢复**是否会被隐藏**」（`entryHidden(undefined, decision)`）。

**踩到的坑，下轮直接用**：

- `setOverride` 读写的表是 **`processing_source_item_overrides`**（键 `source_key+item_id`），
  不是 `processing_entry_overrides`（那张表里是空的）。`overrides()` 会把**全部 input** 都列出来，
  没有行的条目填 `mode:"automatic", revision:0`。
- `setOverride` 带乐观锁，`expectedRevision` 必须取该条目**当前真实 revision**（不能假定 0），
  否则 `AutomationError: revision_conflict`。真机目标 seq=4437 的 revision 是 2。
- 覆盖率会骗人：我先跑 `pnpm --filter Folo run build:web` 被 safe-delete 拦了（`rm -rf out/web` 要
  批量确认），改成 `mv out/web out/.web-pre-<ts>` 再 `WEB_BUILD=1 pnpm exec vite build`。
  另外 `cross-env` 不在 PATH，要用 `pnpm exec` 或直接给环境变量。
- **`turbo run lint` 加 `--filter` 会静默跳过根包任务**（`//:lint`、`//:format:check`），
  看起来"通过"其实没跑。要跑真质量门就别带 `--filter`。
- 本地 locale JSON 有 `recursive-sort` 规则，**键必须递归有序**，插新键后要
  `npx eslint --fix locales/app/*.json`。

## 四、Folo 服务端闭源调研（答用户"能否自建服务端"）

结论：**自建不现实，无可用的开源服务端**。证据（均已核实）：

- 本仓库与 RSSNext org 都没有服务端代码；官方 helm-charts 只含 RSSHub chart，无 Folo 服务端。
- 客户端按"可换服务端"设计：`VITE_API_URL` 可覆盖（`packages/internal/shared/src/env.common.ts`，
  LOCAL 预设 `http://localhost:3000`），desktop 主进程 `api-client.ts` 用 `@follow-app/client-sdk`
  baseURL 指向它。缺的只是服务端实现。
- SDK `src/modules/` 有 30+ API 模块（entries/subscriptions/feeds/ai/wallets/messaging/mcp/…），
  鉴权是 Better Auth（`/better-auth/*`）+ Firebase（登录/推送）。
- 除主 API 外还有**硬编码**辅助域名：`img.folo.is`（`packages/internal/utils/src/img-proxy.ts`）、
  `icons.folo.is`（`utils.ts:240`）、`tts.folo.is`（mobile `tts-core.ts`）、`ota.folo.is`（热更新）——
  自建服务端也覆盖不了这些。
- GitHub 搜过，无第三方 Folo 服务端实现。替代方案：自建 RSSHub 只能控制源抓取，内容仍经官方
  服务器缓存（issue #4550/#4301）；要全链路自托管只能换 FreshRSS / Miniflux / TTRSS。

## 五、订阅限额机制（答"免费版能否突破 150 限制"）

**结论：不能。校验在服务端，改客户端无效。** 证据：

- 限额数值由服务端 session 下发：`user/store.ts` `whoami()` 读 `res.rsshubSubscriptionLimit` /
  `res.feedSubscriptionLimit`，客户端不写死数字（分 feed 与 rsshub 两本账）。
- 服务端拒绝的证据：`apps/mobile/src/lib/error-parser.test.ts` 处理 `"Subscription limit
exceeded\r\nRequest: POST /subscriptions"` 与 `"RSSHub feed subscription limit exceeded"`
  —— 超限时 `POST /subscriptions` 被服务端打回，客户端只解析错误并弹升级框。
- `VITE_UNLOCK_PAID_FEATURES`（`dev-paid-feature-unlock.ts`）只在 dev 构建生效，仅把客户端
  UI 角色提升为 Pro；改不了服务端行为（服务端代理的 AI 也会被 AIRateLimitExceeded 拦）。
- 当前免费额度（folo.is/zh/pricing，2026-09）：feed 150、RSSHub 30、list 1、inbox 1、
  action 1、AI 摘要 3 次/天、翻译 0、TTS 1 次/天。
- 合规省额度路径：RSSHub 名额（30）最稀缺，有原生 RSS/Atom 输出的源直接订阅原生 feed，
  只占 feed 的 150 名额；Trial 角色存在（`UserRole.Trial` + `roleEndAt`），留意官方试用/成就。
