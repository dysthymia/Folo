# 同一公告的融资与产品发布

融资公告常同时介绍产品发布与经营数据。同一公告的多篇报道有互补信息，应生成一条带引用的综述，而不是把互补信息判成重复丢弃。

- 仅从同一段原文中规范已完成融资的金额和轮次，统一“宣布”与“完成融资”的身份。金额、轮次、估值、已知日期冲突，计划或追加融资不能自动归并。
- 仅当主事件是可追溯融资、次事件是同主体的产品发布，且原文明示“融资同时”“同时推出/发布”，才开放整份公告的已采纳事实。无关联证据、周报、分析、教程继续使用原来的分事件许可证。
- 聚合模型逐事实返回覆盖声明，服务端在发布和持久化边界分别核验事实类型、成员、原文引用和综述事实。只有该篇全部已采纳事实都有覆盖记录时，分类和全部列表才由综述替代原条目。材料尚未获取的部分不因此变成已理解；来源主张继续保留归属和不确定性。
- 独有来源主张不能提升为事实；共同事实有另一篇已认可的事实及对应引用支持时，可以引用该事实。推断不得升级为事实。
- 综述更新移除某项事实时，同时撤销对应覆盖记录，覆盖不完整的原文恢复占位。原文链接、人工恢复、来源订阅页与原始已读状态继续保留。
- 旧统一分析草稿仅有片段编号，无法证明片段内每项事实均被覆盖；联合公告使用有缓存的逐事实聚合请求。普通单事件及周报仍使用原共享分析流程。
- 显式历史修复可以指定已保存的已读结果作为上下文，不补抓、不重算单篇、不修改读态；后台默认仍只处理未读材料。
