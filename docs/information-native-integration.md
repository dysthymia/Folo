核验过程中发现并修复：

1. JSX 文本经过 i18next 和 React 双重转义，模型名称及日期显示字面 `&#x2F;`。改为该文本插值由 React 转义，并用真实 i18next 验证斜杠与 HTML 字符安全显示。
2. 历史保存的超宽时间线在缩小窗口时把正文挤出视口。为正文预留最小宽度，在当前窗口临时约束列表宽度，保留用户保存的宽度值。
3. 收藏页沿用普通时间线的未读过滤，已读收藏不可见。收藏查询独立关闭未读过滤。
4. 首屏之外打开的原文没有虚拟行挂载时，正文的原生读态／收藏变化缺少冻结结果同步。正文独立订阅真实 entryId，同步模型与深链状态。

## 追加：去重与后台处理统一（2026-10-04）

本阶段落实去重审查中的执行与数据约束，保留原文、人工恢复及未处理内容。没有启用新的付费范围或重跑历史内容。

- 规则指纹包含 `when` 与动作 `scope`。每个动作独立读取判定和扫描记录，全部动作共用每轮三批、每批八对的调用上限；判完一批后重新预筛剩余对，避免三篇内容的第三对被误标记为已扫完。
- 持久化绑定两侧正文版本、输入序号和代次；换代后晚到的旧结果拒绝落库，读取合并时重新核对规则、来源资格及人工恢复。旧判定缺少新字段时自然失效，原始记录保留。
- 完整正文指纹先处理严格精确重复，不调用模型；短正文还需相同 canonical identity。语义候选保留 48 小时预筛，仅将每侧最多 4,000 字符的完整已采集正文送入模型。缺失或超限正文保存安全否定，不付费请求；正文更新后可重新参与。提示词要求保留新事实、后续进展和独立观点，实际语义效果仍需真实样本验收。
- 当前可读 Story 成员不重复参与模型去重；失效或修复中的 Story 不排除原文。精确合并仅在关系有效保存后排除语义候选；报告总重复关系包含精确关系，精确数量单独记录。
- 后台模式隔离旧 localStorage 去重缓存和旧执行器，旧缓存不再过滤条目或生成合并角标；原始模式与后台原生阅读不执行旧标题过滤。独立 Electron／开发执行器保留原有设置行为。
- 设置页展示有效去重规则、范围、调度、后台共用模型及真实运行报告。管理入口准备未启用内存草稿，只复用已授权 AI 来源。样本预览显示匹配、未知条件与候选对上界，不编造 tokens 或账单预测。
