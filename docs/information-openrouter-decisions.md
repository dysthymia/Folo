# OpenRouter Decisions 接入方案与第一阶段边界

## 目标与当前基线

在现有 `information-service` 的分类 → 标签阅读规则 → 去重 → Story 流程中减少不必要生成。复用版本化标签定义、证据目录、规则优先级、人工覆盖、正文代际、不可变决定与 SQLite 审计；不新增平行的信息处理系统。

2026-10-13 本机分支为 `codex/web-actions-ai-v3`、HEAD `d1c5daf88539fffec03ce3a888a6d577641d6c61`。已有未提交阅读状态、发布工具、去重及 Story 工作继续保留。本次只开发和离线验证，不部署、不切换运行服务、不回跑历史、不 push、不开 PR、不调用付费模型。

## 已核协议

采用直接 fetch 专用 `POST https://openrouter.ai/api/alpha/decisions`，不能经过当前 Chat Completions/Responses 桥。固定模型 `openai/gpt-6-luna-decisions`，接受官方 canonical build `openai/gpt-6-luna-decisions-20261006`，provider 必须为 OpenAI。文本阶段不发送图片、远程图片 URL 或新增媒体材料。

请求为 `state` 与按应用题目 ID 索引的 `questions` 对象。`noul` 是布尔命题的概率，读取 `answers[id].noul`，不使用原生 OpenAI `predicate`；多标签需独立题目。`choice.criteria` 是选项名称到描述的映射。`score.criteria` 为从低到高的等级数组；结果是 0 到 N−1 的概率加权位置，若应用需要归一化必须显式除以 N−1。score 不是置信度。

校验全部题目 ID、type、概率范围、choice 合法选项、score 范围以及 provider/model。`confidence`、`probabilities`、`legend` 可选，缺失不使协议无效；存在时必须合法。缺失主答案、拒绝、错误信封或模型不符均保守保留，不能变成 false。模型概率/自评不等于实测正确率。

参考：[请求协议](https://openrouter.ai/docs/api/api-reference/alphadecisions/submit-a-decisions-request)、[官方技能协议参考](https://github.com/OpenRouterTeam/skills/blob/main/skills/openrouter-decisions/references/decisions-api.md)、[模型页](https://openrouter.ai/openai/gpt-6-luna-decisions-20261006)、[实时目录](https://openrouter.ai/api/v1/models?output_modalities=decisions)。公开输入价格 $0.10/百万 token，输出与缓存读取免费（核验日期 2026-10-13）；结算必须以 `usage.cost` 为准，价格与 alpha 协议可能变化。模型公开上限 200 问题、1,050,000 token，并不作为本地放量依据。

## 分工与最小闭环

| 工作                                 | Decisions                            | 生成模型 / 现有程序                             |
| ------------------------------------ | ------------------------------------ | ----------------------------------------------- |
| 固定标签、多标签、纯噪声与实质贡献   | 定义绑定的 noul，加目录证据 choice   | 版本、范围、冲突保护与规则投影由程序处理        |
| 重要性与噪声                         | 后续评估固定等级；不能以分数直接隐藏 | 个人相关性仍由已核证据和当前 attention 规则计算 |
| 同事件无新增信息                     | 后续仅对现有召回候选做配对判定       | 召回、关系存储、阅读选择沿用现有架构            |
| 摘要、事实、实体、事件名称、投研论证 | 不执行                               | 继续使用生成模型与证据校验                      |
| Story 创建/更新                      | 后续只负责是否有实质增量的门控       | 仍须用户规则授权、事实覆盖与生成模型            |

第一阶段只优化**纯分类与阅读策略**任务：当前文章可能匹配的启用规则中，任何 `ai_transform`、`ai_dedupe` 或 `ai_aggregate` 都阻止快路径，包括尚待标签判断的规则。这样不漏执行标签命中后的生成动作。长文、缺材料和媒体不完备仍遵守现有入口保护。分类路径不伪造摘要、实体或事件；只保存明确的分类说明、原文标题和证据，`facts=[]`，实体未提取保持缺字段。后续规则新增生成需求时按现有显式目标与代际授权补做，不能把缺实体档案标成已提取。

最小闭环：设置显式启用 → 现有未读/来源/历史边界筛选 → 独立 Decisions adapter → 原文证据和版本化 `TagAssessment` → 当前人工纠正 → 既有 `projectSemanticDecision` → 当前 generation 的决定与索引原子发布。关闭时使用原生成路径；无关文章也使用原生成路径。启用不重新入队历史结果。

## 保守策略与模式

- 默认关闭，默认模式为观察。观察模式把供规则使用的评估保持 unknown，原始概率与选择保存在审计中，不能因此自动隐藏。应用模式须显式选择；初始门槛 0.95 是待评估工程门槛，不代表 95% 正确率。
- 标签成立使用 p ≥ 门槛，标签否定使用 1−p ≥ 门槛，中间保持 unknown。模型确认材料不全时全部保持 unknown。正证需选择当前证据目录中一个支持片段；无证据、选 none 或存在明确低置信证据选择时保持 unknown。可选 confidence 缺失不阻止已合法的 choice。
- 独立实质贡献判定复用现有纯噪声冲突保护；有据教程/评测/原始数据/分析不会被局部推广覆盖。
- 接口失败、超长或预算延期：不立即增加生成调用、不自动重试付费，保存固定失败码，标签 unknown、原文可读；材料完整与判断未知分别记录。真正材料缺失继续沿用现有入口保护。
- 程序在发布时再校验正文、代际、规则与人工覆盖；不修改原文、读态、收藏或旧审计。

## 配置、界面、成本与审计

在「设置 → AI → 本机处理模型与密钥」旁提供独立 Decisions 设置：开关、观察/应用、门槛、单篇字符上限、每轮请求上限与独立 OpenRouter Key。端点/model 固定，不允许借自定义地址转发已有密钥。密钥仅保存于既有私有 `ai-config.json`（0600）；公开接口仅返回 `hasApiKey`，空输入保留。保存生成设置必须保留 Decisions 配置，旧配置缺字段视为关闭。

请求限制：每次 ≤200 题、正文默认 ≤12,000 字符、完整序列化请求 ≤128 KiB、30 秒超时、默认每轮最多 20 次；不截断材料后判断“整篇无贡献”。字符/字节上限用于限制请求量，不是可靠 token 或美元预算。OpenRouter Key 应在真实评估前另设支出上限；本地 per-run 上限不等于跨轮/跨进程的月度预算。

SQLite 独立审计记录 inputSeq/contentVersion/generation、接口、协议版本、模式/门槛、请求 ID、实际 model/provider、原始答案、使用量与 USD cost、耗时或失败码。缓存命中沿用现有 metrics/reused，不新增计费请求记录。失败且上游 usage 缺失时 cost=null，不能记为免费。审计不存密钥、Authorization、上游任意错误文本或额外正文副本。设置面板展示请求数、已知成本和未知成本次数；结果详情可用现有 inputSeq 对照审计。成功分析沿用现有模型缓存，指纹加 Decisions 模式/门槛/模型/协议身份，不与旧生成结果混用。失败/预算延期结果不得成为永久模型缓存。

## 去重与综述的后续启用边界

先保留当前完全同文去重与 semantic candidate 召回。新配对 adapter 至少需分开询问 same_event 和 no_new_information：主体、动作、日期、融资轮次、数量/金额和状态均要一致，事实增加、修正、不同事件或缺材料都保留独立可读。不能只凭同主题或同品牌去重。成功 pair 仍写当前 `dedupe` relation/audit，不用分类标签直接替代比较。

Story 门控仅对现有规则已批准的当前候选集合运行；没有实质增量可不生成新版本，有新增事实继续生成并校验事实覆盖。重要更新、冲突事实、截止安排和安全事件不因低重要性分数被跳过。pair 与 Story 门控待专项评估后另行启用，本次未将它们切到 Decisions。

## 评估与逐步启用

1. 离线 fixture：专用路径与请求形状、可选字段、canonical/model/provider、坏 ID/type/range/选项、401/402/429/超时/拒绝、超长、不完整材料、未知与冲突保护、规则优先级、人工纠错、缓存和旧配置兼容、读态/代际不变。验证协议与保护，不宣称模型质量。
2. 真实评估待单独授权：最多 100 篇用户明确批准公开文章，≤12,000 字符/篇，≤100 次请求，不重试，OpenRouter Key 总支出上限 $0.50，测量实际 usage 与延迟。须确认 OpenRouter/OpenAI 目的地、材料清单、独立凭据与额度；不使用未授权私有文章或报告密钥。公开价预计远低于该预算，但不保证真实账单。
3. 人工双标注按任务分层：短公告/长解读/广告混有教程/多事件/相似融资公告/缺正文/中英日材料。报告各标签 precision/recall、unknown 比例、整篇噪声误隐藏、低置信保留率、延迟、每篇实际成本、总调用与生成调用减少量。单独计算阈值曲线和错误实例，不能用概率直接报告正确率。
4. 观察模式小范围运行，检查审计与原文；应用模式先启用客观主题和事件标签，再评估噪声规则。去重误合并与增量漏失分别要求独立验收。设置不扩大来源、水位或历史窗口。

## 独立复核与修复（2026-10-13）

独立只读审查与全闭环 fixture 确认并修复以下问题：材料覆盖答案提供低 `confidence` 时不能确认完整；证据 choice 提供低的所选选项概率时不能成为可靠正证；题目内部的 `refusal/error` 在 Zod 去掉未知字段之前拒绝；标签映射不能丢掉已提供的较低置信信息，从而绕过更严格的阅读规则门槛。应用侧置信值取方向概率、已提供的 confidence/证据选项概率与覆盖可靠性的保守最小值；整篇噪声还受无贡献判断限制。缺失 optional 字段不按零分处理，原始概率仍独立保存在审计中，这个最小值不是实测正确率。

文本阶段另复用现有 `missingMaterialContext` 核验关联正文，并对明确未读取的媒体保留未知；不新增媒体抓取。仅因为材料判断低置信度，不标记正文缺失；已确认缺失材料才使用 `materialCoverage=partial`。保留失败结果不宣称已完成分类。阅读/策略动作之外的关联或装饰链接沿用现有依赖判定，不只因任意链接失败而判整篇缺失。

缓存加入预期 canonical build、标题、原始 HTML、媒体/上下文与已取得关联材料，避免正文转纯文本后丢失图片标记而误复用旧纯文本判断。协议/映射版本升级到 2。完整正文及定义版本、实际提示仍参与指纹；纯阅读规则发布版有意不成为语义缓存失效条件，发布阶段使用所选规则版与人工纠正重新投影，规则版本变化和正文/媒体变化分别有复用/隔离测试。低覆盖、拒绝和失效响应不通过读态或缓存获得隐藏授权。

生成设置与 Decisions 设置的读改写在同一个服务实例串行执行，避免两个界面同时保存丢失配置/密钥。审计读取失败仍显示设置并允许关闭；费用显示不可用，不伪装为零费用。无效数字阻止提交并给出范围；保存失败提示结果未确认，密码框清空，只有确认成功才显示保存成功。
