# Decisions 的逐规则执行器选择

用户明确要求每条自定义规则独立选择是否使用 Decisions。此前全局分任务控件不能替代这个要求；本阶段实现规则字段及实际路由，保留生成模型选择。

规则新增可选 `decisionModel: generation | decisions`。旧规则缺字段时保留既有实际执行路径，不批量补字段、不默认切换；需要生成任务的旧规则仍使用生成判定，不因另一条规则单独选择 Decisions 而连带切换。界面明确显示沿用现有行为。新建规则默认 generation，复制保留被复制规则的选择且默认停用。编辑、保存、发布和重载均由原有规则协议承载，顺序与优先级保持不变。

该字段控制固定标签/重要性/噪声条件的客观判定与语义去重比较。字面条件继续本地求值；摘要、事实、开放式事件命名、改写、综述和论证继续使用原生成模型。规则选择 Decisions 仍需独立 Key 及总开关授权。标签遵循当前观察/应用模式；显式选择 Decisions 的去重规则使用受保护的专用 Decisions 比较，不受旧规则默认去重模型开关影响。失败、拒绝、材料不足或低置信保留原文，不静默追加另一模型付费调用。总开关关闭时，显式 Decisions 规则保留待定，不假借生成答案；旧规则维持原有默认行为。

同文多规则：保留基础生成语义档案，为规则建立各自判定档案与执行器映射。规则条件只读取该规则对应的判定；其它规则继续读取自己的生成或既有档案。公共标签索引在执行器有冲突时保留未知，不把一方结果串给其它规则。每条档案只保留所需标签和引用证据，事实/实体主档案仍复用原系统。仅全部所需固定判定均选择 Decisions 且没有生成任务时，可走原有纯决策短路。阅读投影和人工覆盖仍由现有发布流程负责。

缓存区分实际执行器、canonical model、问题/定义版本、完整材料及媒体/引用状态；规则路由映射绑定执行器指纹，不能误用另一执行器结果。允许同一执行器共享相同客观材料判定，但审计记录涉及规则和缓存命中，生成输出不能冒充 Decisions。去重沿用候选召回和已读/人工覆盖保护，模型切换不批量重跑历史、不改既有结果。正式执行和试运行均复用逐规则逻辑；试运行只写审计，用本次内存缓存，不写正式结果、队列或永久模型缓存。
