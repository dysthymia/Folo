# 本机信息读取边界

本机页面读取已存储的 AI 结果、规则、设置、语义标签、事件、阅读快照、研究记录和集成配置时，使用独立的本地只读会话，不申请 Folo 官方一次性 Token，也不交换凭据或查询官方登录会话。普通收藏分页读取本地缓存；只有显式刷新收藏才同步官方数据。

## 本地会话

- `POST /information/api/local-read-session` 只接受 loopback 连接与服务配置的同源 Origin，数据库必须已经绑定账号。
- 原生页面发送缓存的账号 ID，与数据库 owner 比较；独立工作台使用已绑定工作区。该入口不能创建或更换数据库 owner。
- 随机读取票据仅保存在服务和页面的内存中，有效期五分钟；账号变化或注销时前端立即丢弃会话及进行中的读取。服务每次核验票据和当前数据库 owner。
- `X-Folo-Local-Read-Token` 只能使用共享的 `isLocalInformationRead` 白名单。HTTP 页面仍用空 POST 和 `X-Folo-Read: 1` 承载逻辑 GET，查询 POST 保留原有正文。
- 401 最多重新建立一次会话；账号不符或本地服务故障不会回退到官方授权。Host、Origin 与账号检查继续生效。
- 写入、发布规则、模型试运行、列表处理触发、选材研究和外部同步继续使用原授权流程。本地会话不能调用这些操作。

## 单条结果查询

单条详情和解释将 `inputSeq` 下推到 inputs、published decisions、overrides 和反馈的数据库查询，反馈按当前 decision ID 读取并使用索引。单条事件视图同样按 inputSeq 读取成员并补登记目标事件，不在打开弹窗时同步整个事件库或遍历全部 Story。

全量列表和后台同步保留各自完整处理范围；单条查询仍检查当前正文版本、generation、release、发布指针、可见来源和撤回状态，不能通过减少查询范围暴露旧结果。

2026-10-06 在现有 16,221 个 current inputs 的工作区实测：单条结果读取从约 2,778 ms 降至约 3–18 ms，来源上下文查询从 16,221 次降至 1 次。此数字为本机服务内部耗时，不包含浏览器渲染，且会随同时运行的构建和后台任务变化。

常驻服务于当日等待旧批次结束后更新。Chrome 真实规则页与结果弹窗验收均未请求官方一次性凭据；单条结果 HTTP 请求约 88 ms，同条事件请求约 339 ms，两者均返回 200，携带本地读取票据且没有官方 Token。相关后端、共享范围与前端定向测试共 234 项通过，服务、共享核心和 Web 类型检查及两种页面构建通过。旧分类批次的 Codex 超时属于既有模型执行问题，本次没有重跑模型。
