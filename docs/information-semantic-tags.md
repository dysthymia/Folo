# AI 语义标签：第一阶段实现

本阶段实现文章语义标签、标签阅读规则、持久化索引和人工纠错。继续使用现有规则编辑器、AI 结果面板和阅读投影。第二阶段的独立事件登记与跨来源检索见 [事件实现说明](./information-events.md)；第三阶段的增强去重和事件驱动 Story 更新见 [增量综述实现说明](./information-story-increments.md)。

## 数据与规则

- `subscription_tag` 描述订阅来源；`entry_tag` 描述当前正文，两者独立。
- 内置 30 个版本化定义：形式、信号、主题与事件分别描述客观内容。目录包含安全事故、激励/空投、代币经济变化、上币/交易支持、监管、宏观变化、个人成长及具体经验等定义；用户关注程度独立保存，不改变这些定义。
- 每个评估保存 `present / absent / unknown`、置信度、理由和证据编号。没有评估、定义过期或置信度不足都按未知处理；负条件不会把未知当作不存在。
- 规则按实际依赖请求所需标签。结果面板把尚未评估的其他标签显示为未知，不表示已经分析全部定义。
- 新格式为 `RuleSet.formatVersion=5`，旧格式 4 继续可读。`entry_tag` 支持 `contains_any / contains_all / not_contains_any`，默认门槛 0.9。
- `reading_decision` 独立设置 `visibility=show|hide` 和 `aggregationEligibility=allow|deny`。优先级逐字段处理，未知规则只悬置它可能影响的字段。
- 降噪模板先作为停用草稿加入编辑器，必须明确选择来源。保存草稿不会启动处理或回跑历史。

独立 `ai_classify` 动作显式选择需要评估的标签，沿用本条规则的来源或类别范围。它不会附带隐藏、改写或创建综述；这些动作仍须分别配置。旧规则仅做去重或综述且没有 `entry_tag` 依赖时不会自动申请语义标签。

调度可保存 `classification: { mode: "new_content" | "list_loaded", enabledAt }`。新内容模式由后台计划触发，不依赖用户打开列表；只有首次入库时间不早于启用水位、且在既有来源、历史窗口和当前未读授权范围内的内容可主动分类。正文水合换代不会重置首次入库时间。新保存计划建立当前水位，普通计划编辑保留水位；旧计划缺失该字段时仍沿用列表加载行为，在规则发布建立新模式时才保存水位。暂停状态及原历史边界保留，不启动全历史回跑。

列表加载仍可显式处理本批获准的旧未读目标，显式单篇处理亦可请求分类。后台规则的 `entry_tag` 依赖继续允许必要语义分析，不因关闭主动分类而被剪掉；这不扩大原任务的来源或历史范围。

## 分类、缓存与发布

```mermaid
flowchart LR
  A[授权范围内的当前未读材料] --> B[基础语义分析]
  B --> C[原始标签与证据档案]
  C --> D[叠加当前正文的人工纠错]
  D --> E[重新匹配阅读规则]
  D --> F[命中新的特殊处理提示]
  F --> G[按提示处理并缓存]
  G --> E
  E --> H[当前决定与标签索引原子发布]
```

原始语义档案不随人工纠错或隐藏偏好改写。基础缓存包含原文身份、完整文本、定义、模型/端点/推理强度及真实分析指令；阅读策略、摘要长度和 `global.attention` 不进入语义缓存；纯注意力配置及相应版本号不改变真实分析指令。显示长度在发布时裁剪，原始摘要和证据保留。

标签条件命中特殊 `ai_transform` 提示时，在基础判断完成后执行第二阶段处理。变换缓存独立保存，并保留基础标签判断。改变分析指令、输出语言或实际处理提示仍可能需要模型，不能承诺全部配置变化零调用。

普通单篇与长文共用 `substantiveContribution: { state, confidence, reason, evidenceIds }`，独立于摘要及 `facts` 上限保存可用事实、方法、论据和经验的贡献判断。新语义请求必须提供贡献判断，正证须绑定当前原文目录；旧结果可缺失该字段。置信度至少 0.8 的有据贡献，或教程、评测、原始数据、有据分析的可靠正证，与整篇纯噪声正证冲突时，有效标签变为 `unknown` 并保留冲突解释；原始档案仍保存模型判断，不能直接按该噪声标签隐藏。

长文逐块保留标签、贡献证据和材料覆盖。整篇纯噪声要求全部分块完整且一致，无实质贡献；贡献或未知分块会阻止该结论。主题等存在性标签可以由可靠正证建立，缺失材料不能支持全篇不存在。分块证据不受最终 `facts` 数量上限影响。

档案覆盖与阅读策略分别保存：

| 字段                         | 含义                                                                                 |
| ---------------------------- | ------------------------------------------------------------------------------------ |
| `materialCoverage`           | `complete / partial`，描述供判断的材料是否完整；不能由标签未知或置信度门槛反推缺正文 |
| `semanticAssessmentCoverage` | `complete / partial`，记录原始标签评估是否含 `unknown`                               |
| `coverage`                   | 保留旧合并语义兼容；旧记录只有该字段时不能无损推断上面两项                           |
| `pendingPolicyFields`        | 决定中尚未解析的 `standalone / aggregation / rewrite` 字段，保留待定原因             |

材料可读但低置信度或未知标签使规则待定时，原文保持 `status=keep`、`standalone=always`。`needs_context` 仍表示实际材料不足，不能把它作为规则待定的替代名称。模型 `disposition=hide` 只是语义建议，正式隐藏须来自明确阅读策略或经过证据比较的专用去重；缓存复用也重新核验隐藏授权和原文引用。

发布和索引都核验当前正文、代际、规则版与决定指针。晚到结果不能覆盖更新后的材料或人工纠错；同代际的重复发布使用首个不可变结果。

## 纠错与查询接口

路径相对 `/information/v1`：

| 接口                                               | 行为                                                                     |
| -------------------------------------------------- | ------------------------------------------------------------------------ |
| `GET /processing/semantic-tags`                    | 读取内置定义                                                             |
| `GET /processing/entries/:seq/semantics`           | 原始档案、有效判断、纠错修订号和决定指针                                 |
| `POST /processing/entries/:seq/semantic-overrides` | 按正文版本、修订号和请求 ID 覆盖指定标签，或恢复自动判断                 |
| `POST /processing/semantics/query`                 | 标签包含/排除、来源、未知状态与快照分页；完整范围先筛选，再分页          |
| `POST /processing/recompute-decisions`             | 显式选定已有画像，使用当前生效规则重算阅读决定；核验正文、代际、决定指针 |

人工覆盖独立持久化，只作用于指定正文版本。纠错更新阅读决定和索引，并失效相关 Story 材料资格；不自动请求模型、不修改已读或收藏状态。新的专用处理提示若尚未执行，维持可见的待处理状态。

显式重算只复用已有语义；新的分析/语言/处理提示依赖不能被伪装为已经执行。新增标签没有旧评估时保留未知。查询计数同时给出范围总数、已索引数、匹配数和未知数，查询接口不会因此扩大采集范围。快照绑定账号、可访问来源与撤回名单，最多保留 100 份、24 小时失效。

## 条目列表标签

全部和文章的紧凑列表优先完整展示标题及其后的全部标签，简介仅使用剩余宽度；窄栏允许标题和标签换行。社交媒体放在作者、时间旁，图片、视频和音频放在来源、时间旁，其余标签通过「+N」展开。左侧已完成状态图标直接打开已保存的 AI 结果弹窗，普通条目右侧不再重复显示结果按钮；点击图标不会触发原文导航。

结果弹窗读取数据库中已经保存的决定和证据，不实时调用模型。单条查询按 inputSeq 限定范围；本地结果、规则和设置读取使用独立的本机只读会话，详见[本机信息读取边界](./information-local-read.md)。

`GET /processing/entry-results` 的批量身份索引包含当前有效的 `semanticTags`，仅展示 `present` 标签，复用人工纠错索引，并核验正文版本和当前决定指针。没有结果或尚未评估的条目不显示推测标签；列表不会因此逐篇请求模型。人工纠错成功后，立即失效并刷新批量索引。

## 领域、事件与具体名称

2026-10-07 新增独立事件类型与实体提取。`topic:product` 定义升至版本 2：关注真实产品的功能、设计、开发、发布、使用或评测；机构扩张、融资、资产交易及持仓变化本身不属于产品内容。版本 1 的判断在现行列表和规则中按未知处理，原始档案保留供审计。

领域与类型分开保存，只在确定有单一领域归属时组合展示，例如「区块链-产品」「AI-产品」「区块链-机构增持」。DeFi、基础设施等细分域独立展示；多领域或多事件不根据平面标签猜测相互关系。订阅目录仅限定执行范围，不决定文章领域。资金流标签描述有明确对象、时间或统计口径的流入、流出或净流量；价格变化、单笔转账和机构买入不自动命中。

语义请求必须返回 `entities`（无可靠名称时为 `[]`），区分 `organization / project / product / asset`，记录 name、parentName、aliases、confidence 和 evidenceIds。名称、所属及别名必须出现在本条所选原文证据中，拉丁缩写须完整匹配，实体不按相似拼写合并。详情保留所有实体与证据，列表只投影置信度至少 0.9 的主要名称，产品可附带明确所属名称。

档案沿用 schemaVersion 2，新增可选 `entityVersion=1` 和 `entities` 兼容旧结果；未提取实体的旧档案不标记完成。分块独立保存实体证据，最终综合仍能选择 facts 摘要之外的后文名称。请求及分块缓存版本已升级，避免复用不含实体的新格式结果。

`entry_entity_index` 随当前已发布决定写入，与正文版本、代际和决定指针绑定。`GET /processing/entry-results` 一次读取 `semanticTags` 和 `semanticEntities`，列表没有逐条详情请求或实时模型调用。新的标签、过期定义和缺失实体只在本次明确授权的列表目标、新内容水位内目标或原有语义依赖任务中补齐，不自动重跑全部历史；实体独立检索与人工实体纠错尚未加入。

## 独立注意力

`global.attention` 保存用户明确选择的关注清单 `{ id, name, aliases }`、启用状态和临近截止窗口 `nearDeadlineHours`（1–168 小时，默认 48）。清单可为空，不推测用户持仓或偏好。规则动作 `attention: { level: "important" | "urgent", reason }` 只决定阅读提示，不改变客观标签、隐藏、综合资格或读态。

当前读取结果可投影 `attention: { level: "none" | "important" | "urgent", reasons, matchedWatchIds, deadlines }`。重要或紧急需要当前有据的实质变化/贡献以及关注关系；自动升级紧急还需同证据关联的安全事故或可计算近期限。背景提及关注对象不能把另一对象的事故升级为紧急，广告中的“紧急”也不能生成截止日期。缺年份、明确时刻或时区时保留原文期限及 `unknown`，不猜时间。

只变更关注清单或注意力动作时仍保存规则发布版本，但即使选中既有条目，也不改变它们的处理代际、状态或规则指针，不重新排队模型。注意力由当前有效配置与已有证据投影；真实语义指令、标签定义或处理提示变化仍沿用相应授权流程。

## 当前边界

本地主应用的「设置 → 标签设置」提供独立的定义目录，按领域、事件、形式和信号分组，支持搜索名称、定义、别名与正反例。目录通过现有本机只读会话读取 `GET /processing/semantic-tags`，展示服务端当前定义及版本，不调用模型、不申请官方一次性凭证。内置定义目前只读，启用哪些标签仍由处理规则控制；目录不是按标签检索文章的阅读面板。具体机构、项目、产品和资产名称属于条目实体，不计入固定定义目录。

规则条件与标签分类动作采用同一多选控件：已选项显示为彩色标签，可用 × 移除；点击添加后按领域、事件、形式和信号分组选择，支持名称与别名搜索、连续多选、方向键与 Enter 选择、Esc 关闭及清空选择。修改只更新规则草稿，保存和生效沿用原有流程。

2026-10-06 的真实账号验收仅为 Blockchain 类别启用标签分类，只处理列表当前加载的未读条目，没有执行历史重跑。语义查询后端已提供；现有阅读界面通过规则与结果面板使用语义，独立的标签检索面板尚未加入。第二阶段已接入独立事件登记；第三阶段已补充 Story 的增量差异更新。

验证采用假模型和实 SQLite：首次语义分类、批量证据隔离、长文覆盖、未知保护、策略缓存复用、标签选中处理提示、纠错幂等/回滚、陈旧发布和查询分页均有定向测试。前端验证覆盖条件、动作、草稿、结果展示和纠错交互。

本说明记录当前源码接口与本地定向验证边界，不代表已部署或已完成所有真实来源验收。当前处理不因新增字段而具备视频帧、音频、字幕或未读图片理解能力；缺失媒体证据继续保留未知。
