# Folo AI 自动化使用与运维

所有入口均在 `http://local.folo.is`。使用已有 Folo 登录，无需再绑定一个工作台账号。

## 设置规则与模型

1. 打开 [自动化](http://local.folo.is/action)，点击「新建规则」。本地域名统一使用单规则编辑器，旧本地规则也列在这里；Blockchain 只是其中一条用户规则。
2. 条件支持 ALL、AND/OR、订阅、分类与视图、私人标签、List 成员及正文属性。上方规则的明确字段优先；语义要求共同进入模型指令。来源/分类/视图右键菜单可打开或预填统一规则。
3. 同一规则可以添加屏蔽、静音、AI 筛选、AI 摘要、翻译成中文、自定义 AI、语义去重或同事件整合。翻译会预填逐段翻译为简体中文的要求，译文在原时间线的「AI 结果」中查看，原文保留；若材料不完整或超出输出长度，会要求注明翻译范围。只包含屏蔽、静音的规则不会调用模型。展示策略等较少使用的设置收在高级选项中。
4. 选择未读条目先查看命中与覆盖；“AI 试运行”显式调用当前模型，展示原文、已发布结果与草稿结果的差异和引用。它不发布草稿、不重排生产队列、不更改阅读结果；已读或读态未知时明确拒绝调用模型。
5. 「保存并生效」只发布当前规则，不顺带发布其他草稿，也不触发历史内容重跑。停用规则后不再由它触发后续 AI 处理。公共要求和运行时间在「公共设置」中分别保存；版本、导入与批量发布工具保留在高级管理中。

日常 AI 的处理目标必须当前明确未读：正文水合、单篇处理、事件综述、综述修复和普通试运行都遵守这个限制；规则只能继续缩小范围。去重可以只读参考本次任务截止时间前 24 小时发布的已读缓存材料，不重新抓取或处理已读正文，不改变其阅读状态。读态未知时等待同步，已读不触发新处理，也不抹掉原有结果。各阶段开始时检查当前快照，上游尚未同步的变化或已经发出的模型请求无法据此实时撤回。“处理成功”表示单篇决定已校验并保存，与读态独立；去重还要求保留决定及其他参与资格成立。显式历史选材研究仍使用用户另外选择的范围。

「执行策略」中的「打开并加载列表后自动执行」默认开启。打开全部、分类、订阅源或 List 的普通条目列表，加载完成后会异步把本次加载条目的元信息送入后台队列；原始内容模式也可触发，不阻塞阅读。仅已发布 AI 规则覆盖、计划允许且历史窗口内的明确未读条目成为处理目标；收藏、预览与生成综述页不触发，未知读态等待后续同步。

列表触发与定时、手动执行共用材料缓存和有界联合分析；单篇结果、去重覆盖判断与新事件综述可在同一次模型请求中产生，分别校验证据与输入代际后保存。先落实去重关系，再执行综述；已处理积压、跨批新增对照、长文和既有事件更新可基于缓存材料或已提取事实按需补做。翻页目标会合并到待执行批次，运行中的目标范围保持冻结；重复加载有短冷却，正文或发布版本变化仍可重新评估。列表批次不扫描全部历史，后处理仅推进与本批条目相关的综述或去重候选。「启用后台自动化」是自动触发总开关，可保留定时执行而独立关闭列表触发；暂停后不再新增列表或定时任务。

在头像菜单打开「设置 → AI → 本机处理模型与密钥」，选择模型来源：

- 「Codex 模型」从本机 Codex CLI 的模型目录选择，使用已有 Codex 登录，无需另填 API Key。可选择「推理强度」，选项跟随当前模型的支持范围；保存后用于后续调用。旧配置未选过强度时保持 low。目录和执行共用同一 CLI，优先使用显式 `CODEX_BIN`，其次客户端内置 CLI，再回退 PATH 中的 Codex；因此不会把旧版 PATH CLI 的内置目录误当成当前客户端全部模型。目录只说明本机 CLI 支持的模型；账号的实际使用权限仍由调用时确认。目录不可用时显示明确提示，缓存目录会标为可能过期。
- 「自定义模型」填写模型名称、API 基础地址和 API Key，接口需支持 OpenAI 兼容的 Chat Completions 与结构化 JSON。基础地址填写 `/v1` 等路径，服务自动追加 `/chat/completions`。可点击「使用千问配置」复用原有千问地址；换到其他地址需提供该地址对应的密钥。

切换选项只修改草稿，点击「保存设置」才生效。此配置共用于后台信息处理、AI 试运行和本域名本机 AI 聊天；原 Folo 云端与 BYOK 配置保持独立。新调用使用新设置，已发出的调用与历史结果保留原模型；已固定旧配置的处理任务不会悄悄换模型、强度或地址。密钥仅保存在本机私有文件，网页只显示是否配置；不同地址或推理强度不会混用模型处理缓存。推理强度目前仅用于 Codex 模型，自定义接口仍按原有兼容方式执行，不假定其支持 Codex 的全部档位。自定义模型经 Codex CLI 执行，每次调用使用 Folo 独立临时 `CODEX_HOME` 和 profile，不改 Codex 客户端的全局模型配置。

## 标签与 List

在订阅管理的“我的标签”列筛选、多选并批量添加或移除标签；也可在 Actions 标签管理从分类或已核验的 List 选择成员。标签是处理服务内的私人数据，改名保持稳定 ID；仍被规则引用的标签不能直接删除。

List 按 ID 区分，界面显示所有者稳定 ID、同步状态、修订和时间。只有后台保存为完整的成员快照才能辅助批量选择；未知、失去权限或未同步不等于零成员。上游未返回所有者时显示未知，不做推断。失效分类需要手动重选对应身份，不能通过猜测改名关系继续发布。

公开模板导出默认移除账号和私人来源身份，并将规则停用。Prompt 文字会保留，应在导出预览中检查其中的私人内容。完整私人备份需明确选择；导入只修改未保存草稿。

## 去重与事件综述

普通报道的 `+N` 表示完整重复组中折叠的报道数，不受浏览器当前加载了多少篇影响。悬停即显示前几篇报道的标题和来源，不发起详情请求。点击角标（键盘可用 Enter/空格）展开详情，顶部显示保留文章及原文链接，可分页查看成员标题、来源、发布时间、折叠理由和原文链接。组成员支持逐条「保持独立显示」；操作后回到列表并显示「已手动保留」，点击或悬停此标识可恢复自动处理，重新按当前规则折叠。原文和读态保留。详情立即显示时间线已同步的元信息和折叠理由，不等待网络请求；后台只核验当前重复组的最新关系和恢复状态，完成后提供「保持独立显示」按钮。同账号、同关系版本的明细在一分钟内复用，账号切换、关系变化和恢复操作会失效缓存。详情读取失败可重试，后台组关系变更时重新读取当前组；恢复最后一个成员后，面板显示完成，关闭后角标消失。综述角标使用服务端完整材料数，继续点击阅读综述。

在头像菜单的「设置 → AI → AI 去重」查看后台有效规则、来源覆盖、共用模型与最近完成的去重报告。此处的「管理去重规则」打开统一规则编辑器；没有现有去重规则时，仅在已授权 AI 来源内准备未启用的内存草稿。打开入口和查看预览不会保存、启用规则或调用模型。预览统计缓存样本的命中、未知条件及候选对上界，不代表完整历史范围或精确费用；AI 试运行可能消耗用量。

后台先识别严格相同的已采集原文，这一步不调用模型；不同正文用标题与摘要预筛 48 小时内的语义候选，再用双方已采集正文判重。正文缺失或超出 4000 字符上限时不调用语义模型，也不凭摘要隐藏。已采集正文可能是订阅源提供的摘要，不代表已另行获取网站全文。

语义判重先逐侧核对实质信息。双方信息等价时可合并；A 完整包含 B 的全部信息且增加其他信息时，保留 A、隐藏 B，不受发布时间或篇幅影响。双方各有对方没有的信息、事实或结论冲突、无法确认完整覆盖时，双方照常显示。措辞、排版、来源署名、报道模板日期和等价数值写法不算新增信息，真实事件日期、条件、程序、后续进展、观点和结论仍须核对。合并只隐藏被完全覆盖的条目，覆盖证据写入去重报告；连续包含的多篇报道统一关联最终完整报道；折叠理由逐段标明实际比较的标题与覆盖方向，不把包含链写成未经比较的直接结论。新版判定规则升级后，旧版去重判定不再作为本版隐藏依据，在当前未读范围内按预算重新评估。每轮全部去重动作共用最多三批模型调用、每批最多八对的预算，未判完的候选留到下一轮。

已读参考范围按发布时间、相对任务固定截止时间回溯 24 小时；这与未读候选之间原有的 48 小时发布时间差预筛是两个边界。未读内容已被已读参考完全覆盖时折叠未读条目；未读含新增信息、双方冲突或无法确认覆盖时保留未读，已读参考始终不作为隐藏目标。当前可读事件综述已经覆盖的材料不重复交给去重模型；综述失效或待修复后，原文重新具备参与资格。去重只保存合并关系，原文与全部来源保留，原始内容模式和人工恢复仍可查看。修改规则条件、正文版本或人工恢复会让不再适用的旧合并失效；后台模式不再用旧浏览器缓存隐藏条目。未处理内容继续照常显示。

精确去重同时核对标题、正文、摘要和已有引用材料，跨原文还需满足 48 小时发布时间差限制。同文报道按当前时间窗选择可见代表，较早的同文不会阻挡后续窗口内的折叠；同一原文延迟进入不同订阅不受这个跨原文时间限制；不同标题、附件身份无法核验或上下文缺失时不做精确自动隐藏。Feed/List 中的同一原帖不会与自己调用模型比较，来源上下文仍分别匹配规则。媒体或引用未补齐时不做语义隐藏。

判定缓存区分明确结论、无法判断、正文不完整、模型漏答与无效回答。置信度低于 0.85 的否定同样归为无法判断，不记作已经证明不同；旧缓存读入时遵守同一条件，不清空全部缓存或增加周期性付费重试。漏答或无效回答在后续任务中至少冷却一分钟，最多补判一次；仍无结论则保留原文并停止自动付费。无法判断或材料不完整等待正文补齐、输入换代或判重版本变化后再评估。后台报告的 `unresolved` 表示当前未得到明确结论的关系，与预算积压 `pending` 分开；停止重试不表示已经证明两篇不同。本轮判重版本升级使旧关系失去本版隐藏资格，保留原文和旧记录，仅在现行规则覆盖的未读范围内逐步重新评估，不自动重算全部历史。

候选预筛先排除可本地确认的严格同文，再用共享 bigram 的倒排检索逐条选择最佳候选；保持原有阈值、48 小时窗口、排序和单轮预算，不将未入选候选登记为已证明不同。内容关系按实际模型证据和判重版本保存，与每条规则的应用关系分开：重叠规则及后续同证据任务可复用一次比较，正文、标题、来源或时间变化后重新比较。当前规则范围、未读资格与人工恢复仍先核验，关系缓存不能绕过它们。

后台报告分别显示共享结果应用、内容缓存命中、独立比较、预算积压与未得结论的关系。独立比较只合计已知用量；没有供应商计数的请求另列为未知。参与去重的共享请求总用量已计入单篇处理，只用于解释成本，不与单篇再次相加，也不伪造按功能分摊。`codex-usage.jsonl` 每次执行只记录一行请求身份、任务类型、文档/配对数量、提示及 schema 字符数、排队与执行耗时、用量；执行耗时包含本地准备、CLI/桥接、模型和输出校验，并非纯模型生成时间。账本不保存文章、模型原始响应或密钥。

## 计划与阅读

来源由启用的 AI 规则条件自动确定，不必在计划里重复选择。分类条件会跟随新增订阅；固定订阅条件保留明确名单。第一条 AI 规则启用时创建默认计划，后续修改保留已有运行时间、历史起点和暂停状态。

原时间线中已有 AI 摘要的条目可点击「AI 结果」，按需查看标题、摘要和处理理由；原文保持不变。

计划支持每日 08/12/15/20/23、自定义时点、已保存时区、历史起点、手动执行及可选轮询。`ready_by` 会提前启动以争取在目标时间就绪，不保证模型和网络一定按时完成。关闭浏览器不影响已启动的本机服务；机器睡眠、关机或退出 macOS 账号时不会持续执行，恢复后按持久化计划追赶。

原时间线工具栏可切换「原始内容 / AI 处理后」，两态共用原生虚拟列表、分栏和阅读区。「全部」、分类、单个订阅源、List 和收件箱都保留官方条目，并按同一阅读范围叠加事件综述；未处理、未纳入规则或等待补充材料的条目照常显示，处理模式只对已有决定应用过滤，原始模式保留原文。普通条目仍由原有官方查询分页，不以本机采集库存代替全部订阅内容；切换模式不会自动调用模型。综述复用原生列表样式，左侧「事件综述」只是仅查看该来源的入口。搜索、主题和日期筛选收在独立综述来源的工具栏浮层中；普通时间线保持原有搜索语义，旧 AI 筛选参数不单独收窄其中的综述。收藏入口同时包含全部官方收藏和私人综述。综述结果基于固定快照，有新结果时提示刷新；主动纠错和失效材料会立即更新可读资格。

单篇详情可看原文、处理理由、实际发布版本与命中规则，并跳到来源规则。Story 可查句段引用和更新记录、标记该版本已读、移出成员、合并、拆分为其他 Story 或独立项，并在版本条件允许时撤销。Story 已读与原文 read 分开维护，不默认批量修改原文状态。

## 迁移与排错

旧 cloud Actions 保留独立兼容入口。选择可转换的旧本地规则会进入统一编辑器，保存成功且已发布缓存落盘后才停用原副本。正则等不能等价转换的条件保留原规则，提供原编辑器入口，不静默丢弃。

已有独立处理计划时，先点击「保留原范围并升级」：把旧计划的来源限制写入原 AI 规则，再改为由规则决定范围。升级保留历史结果、运行时间及暂停状态；旧 AI 规则存在草稿冲突或范围包含不能安全转换的 List/inbox 容器时，会明确阻止升级。升级不会自动处理内容。

阅读页状态条展示当前固定快照的数量、来源完整度、当前运行和下次启动；Actions 的运行记录和诊断提供具体失败分类。获取不完整应检查来源分页/授权，条件 unknown 应检查元数据，模型失败与 Story 整合失败分别记录，不能把其中一种当作“没有重要内容”。合格单篇在整合失败时可独立阅读。

X 搜索、Notion 保存和研究任务是可选扩展，需要单独配置。Notion 通过显式确认和 outbox 保存；没有真实配置与联调时，不把 mock 测试当作已完成外部写入。核心阅读不以这些集成为前置条件。

## 部署与数据恢复

运行与升级命令见 [服务 README](../apps/information-service/README.md)。常驻服务名为 `is.folo.local.information`，仅监听 `127.0.0.1:2240`。运行产物位于 `~/Library/Application Support/FoloLocal/information-runtime`，前一个构建保存在相邻 `information-runtime-previous`。安装器在有运行任务时拒绝切换。

业务库位于 `~/.local/share/folo-information-p0/information.sqlite`，规则、标签、发布、计划、快照和纠错在服务端持久化；清浏览器缓存不会删除这些数据。数据库与凭据文件权限为 0600。升级前使用 SQLite backup API 制作一致性副本并验证 `quick_check`，不能只复制正在使用的主文件而遗漏 WAL。凭据单独备份到受信位置，不附在公开问题报告或规则模板里。

恢复时先停止本服务，保留当前库及 WAL/SHM 和现有产物，核验备份后将一致性备份恢复到数据目录，再启动服务检查版本和范围。不要用清库处理迁移失败。账号不匹配时页面拒绝读取已有账号的数据；重新登录后由本机读取会话核验账号。读取已保存结果和规则不申请官方凭据，实际同步与写入仍使用原授权流程，详见[本机信息读取边界](./information-local-read.md)。

程序测试验证执行与数据约束；100–200 条用户确认样本、真实非空 List 权限和长期容量属于效果与环境验收，单独记录在 [开发与验收台账](information-v3.1-progress.md)。
